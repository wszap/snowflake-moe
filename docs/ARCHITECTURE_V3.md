   └───────────────────┘
             │  要求分发
             ▼
   ┌───────────────────┐
   │  细胞器 Organelle  │   没有路由！
   │                   │   自发分工：谁干多少，自己决定
   └───────────────────┘
             │
             ▼

   │   忆点（整理输出）  │
   └───────────────────┘
             │
             ▼
   ┌───────────────────┐

**核心主张（与主流 MoE 的根本区别）**：
主流 MoE 有一个显式 router，由它决定「这次叫哪几个专家」。
你的设计**没有 router** —— 核架把上下文交给忆点，忆点自己形成激活分布，
细胞器按这个分布**自发**决定分工。分工是涌现的，不是指派的。

## 四、v3 架构：补上核架（先筛选，再给忆点）

**已确认**：核架不是把全文整段交给忆点，而是**先筛出「最符合本次要求」的信息**，
再把筛选结果交给忆点。所以核架是**两级**结构：

```
① 收集 collect —— 因果全文关联，让每个位置都看见自己的过去
② 筛选 select  —— 选择门：按当前位置的需求，只保留最相关的 top_k 条
③ 交给忆点     —— 忆点拿到的是【筛选后】的上下文，不是全文
```

```
x = embed(tokens) + pos                    ← 补位置编码（几乎零成本）
for each layer:
    ctx = Scaffold(x)        # ①关联 → ②筛选 → 整理好的上下文
    x   = x + ctx
    x   = x + Organelles(x)  # 忆点接收筛选后的上下文，自发分工（替换 FFN）
out = head(Norm(x))          # 经安全机制后输出
```

### 为什么核架是两级，而不是一层注意力

| | 过去全部参与？ | 权重 | 语义 |
|---|---|---|---|
| 普通注意力 | 是 | 软，都非零 | 全收，只是权重不同 |
| **核架筛选** | **否，只留 top_k** | **硬稀疏，其余严格 0** | **先关联，再筛掉不相关的** |

这是核架与 dense baseline 的**本质区别** —— 不是「有没有上下文」，
而是「上下文是全收，还是先用再筛」。这也给了你一个可消融的卖点：
`select_mode` 可切 `topk` / `soft` / `none`，直接对比"筛选这一步值多少"。

### ⚠️ 筛选门的一个真实隐患（已修复并验证）

当 `t < k-1` 时，合法历史不足 k 条，`topk` 会把被屏蔽（`-inf`）的**未来位置**
也选进索引。它们的 softmax 权重是 0，**数值上**不影响输出 —— 但 `gather`
会把**计算图连到未来**，一旦后续加直通残差或改动门控，立刻变成真泄漏。

numpy 复现验证（128 行）：

```
修复前：索引指向未来的条数 = 496   ❌
修复后：索引指向未来的条数 = 0     ✅
        无 NaN，各行权重和 = 1.0
        改未来 → 过去输出差异 0.00e+00  ✅
        修复前后输出完全等价（clamp 只断图，不改数值）
```

修法：`topi = torch.minimum(topi, arange_t)` —— 索引永不指向未来，
被 clamp 的位置权重恰为 0，`0 × h2[t]` 与 `0 × h2[j]` 等价，数值不变。

**这是 MoE 的正确定位**：
MoE 在原论文里替换的是 Transformer 的 **FFN**，注意力层原封不动。
核架承担「跨 token 信息流」，细胞器承担「条件计算与参数效率」。
各司其职 —— 之前是让细胞器兼任了核架的活，所以它做不到。

### 撤掉泄漏，一行搞定

`chunk_size=1` 时 `_chunk_view` 返回 `P=1`，`xc.mean(1)` 就是 token 自身：

```python
xsum = xc.mean(1)   # chunk=1 → xsum == x，零泄漏
```

**所以只需把 chunk_size 设回原默认值 1，泄漏自动消失。**

## 五、核架的三个候选方案（我的判断）

| 方案 | 优点 | 缺点 | 我的建议 |
|---|---|---|---|
| **A. 全文因果自注意力** | 效果最直接；能和 dense **公平对比**；实现成熟 | O(T²)；加参数 | ⭐ **先上这个** |
| B. 线性循环（Mamba/RWKV 类） | O(T)；天生单向不可能泄漏；最省算力 | 实现复杂，调参经验少 | 跑通 A 之后试 |
| C. 跨 chunk 循环状态 | 改动最小 | 信息仍是压缩过的，不如 A/B | 不推荐单独用 |

**选 A 的理由**：现在最紧要的是把对比做公平。dense 用的就是因果注意力，
核架也用因果注意力，两边才站在同一起跑线 —— 那时比的就是「同样的上下文能力下，
细胞器这套稀疏 FFN 省了多少算力」，这才是你真正的贡献点。

⚠️ 用 A 时必须用 `F.scaled_dot_product_attention(..., is_causal=True)`。
**不要手写 `triu` mask 再传进去** —— 之前 dense 就是这么写反的，
`True` 在 mask 语义里是「参与」不是「屏蔽」，导致模型只看未来，loss 崩到 0.019。

## 六、安全机制：能做什么、不能做什么

你的要求是「防止自己操控，要经过人同意，符合安全与国际要求」。
这是**治理层**问题，我必须诚实说明架构的边界。

### 架构能做到的三件事

| 抓手 | 实现 |
|---|---|
| **不可绕过** | 门放在所有细胞器之后、输出头之前。细胞器的 wiring 只决定内部计算，无法绕开门 |
| **可审计** | 记录哪些忆点/细胞器被激活（wiring 稀疏激活天然可追溯）→ 每个输出能回答「为什么」 |
| **可拒绝** | 超出授权范围时走拒绝/降级通路，不产生输出 |

### 架构【做不到】的，必须在系统层落实

- **判断什么算高风险** —— 策略来自人，不能由模型自己定义
- **真正拦住执行** —— 模型只能「提议」，执行权必须在人手里（提议/执行分离）
- **合规认证** —— 需要外部审计与流程，不是架构能自证的

### 对应国际要求（如 EU AI Act 思路）

| 要求 | 本架构的支持方式 |
|---|---|
| 透明度 / 可追溯 | 忆点激活记录 → 输出可解释 |
| 人类监督 | 高风险输出暂停，交人确认后才放行 |
| 无自主目标 | 推理期忆点与细胞器参数冻结，不可自我修改、不可自设目标 |
| 鲁棒性 | 拒绝/降级通路 |

**一句话**：架构负责「不可绕过 + 可审计 + 可拒绝」，
真正的合规在系统层。别指望单靠架构保证安全 —— 那是过度承诺。

## 七、FLOPs 优势要重新算（诚实版）

```

          ≈ 0.776x
```

**论文里应报**：
- FFN 部分：0.664x ✅（这是你的贡献）
