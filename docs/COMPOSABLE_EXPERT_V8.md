# v8 真·拼专家：从「拼不起来」到「拼 k 个 = k 倍容量」

日期：2026-10-18

---

## 一、改动前审计：根因（数值证明，非猜测）

旧版 `snowflake_B.py:184-193` 的合成方式：

```python
U1 = wiring @ W1_U.view(n, -1)      # [C, d, rank]  ← 各细胞器因子的加权平均
hh = silu( x@W1_base + (x@U1)@W1_V )
out = hh@W2_base + (hh@U2)@W2_V
```

**要害：`W1_U` 是 `[n, d, rank]`，所以 `U1 = Σᵢ wᵢ·W1_U[i]` 的形状永远是 `[d, rank]`。**

`audit_before.py` 实测（d=64, rank=4, n=384）：

| 混合细胞器个数 k | U1 形状 | rank(U1) |
|---|---|---|
| 1 | (64, 4) | **4** |
| 4 | (64, 4) | **4** |
| 16 | (64, 4) | **4** |
| 384 | (64, 4) | **4** |

**秩恒为 rank=4，与 k 完全无关。**

再测整层 Jacobian 的秩（`verify_composable_expert.py` 第①条，d=128）：

| 拼 k 个 | 旧：rank(J) |
|---|---|
| 1 / 2 / 4 / 8 / 16 / 32 | **32 / 32 / 32 / 32 / 32 / 32** |

恒等于瓶颈宽度 h=32，**拼 1 个和拼 32 个完全一样**。

> 这就是「32 人挤 4 人道」的数学表达：
> **「拼」这个动作发生在瓶颈内部，最后所有细胞器还是挤过同一条 32 维通道、同一个 silu。**

### 这也解释了四次失败

| 尝试 | 为什么白搭 |
|---|---|
| rank 4→64（+59M 只换 0.223） | 扩的是 `[d,rank]` 因子，出口仍被 h=32 封死 |
| clone 复制组队 | 复制再多秩-4 标本，合成后秩还是 4 |
| 挂谷 ×2 | 旋转/反射是等距变换，秩是旋转不变量，且不加非线性宽度 |
| pair 二阶协作 | 同样在瓶颈里打转 |

四次改造都在瓶颈前后打转，**没有一次碰瓶颈本身**。

## 二、改动：从「先混合参数再共享非线性」→「各自非线性再加权求和」

```python
hᵢ  = silu( x @ E1ᵢ )                    # 每个忆点独立做一次非线性，宽 h_cell
out = base(x) + g · Σᵢ wᵢ · ( hᵢ @ E2ᵢ )  # 加权求和
```

**关键数学恒等式：**

```
Σᵢ wᵢ σ(xE1ᵢ)E2ᵢ  ≡  [σ(xE1₁), …, σ(xE1_k)] @ vstack(wᵢE2ᵢ)
                                              ^^^^^^
  ⚠ 修正(2026-10-18 审核)：原文写 blkdiag 是错的 ——
    blkdiag 拼出 [k·h_cell, k·d]，与目标 [d] 形状不符（实测 (256,) vs (64,)）。
    正确写法是 vstack 垂直拼接 → [k·h_cell, d]。实测误差 1.7e-16。
```

即 **「加权求和」≡「把 k 段隐层拼起来再投影」**，拼后等效宽度 **= k × h_cell**。

不需要动态 shape，也不需要真的 concat —— 加权求和就是拼接。

### 三条主张如何兑现

| 主张 | 兑现方式 | 自检 |
|---|---|---|
| **自主选拼** | wiring 完全沿用内生机制（忆点匹配 + 核架），不引入外部路由器 | 第⑥条 |
| **真扩容** | 拼后等效宽度 = k×h_cell，随 k 线性增长 | 第①②条 |
| **高效** | 只算 top-k 个专家，每 token FLOPs 远低于 dense | 第⑤条 |

## 三、改动后自检：6/6 通过（纯 numpy，10 秒）

```
① 拼装容量（决定性）
   拼 k 个 │ 旧 rank(J) │ 新 rank(J) │ 新等效宽度
       1  │     32     │     40     │     40
       2  │     32     │     48     │     48
       4  │     32     │     64     │     64
       8  │     32     │     96     │     96
      16  │     32     │    127     │    160
      32  │     32     │    128     │    288
   → 旧：恒定 32（与 k 无关）
   → 新：40→48→64→96→127→128，随 k 线性增长（到 d=128 封顶）
```

```
② 加权求和 ≡ 隐层拼接     最大误差 5.551e-17   ✅
③ 零门初始化严格恒等       max|out(g=0)-base(x)| = 0.000e+00   ✅
④ 无梯度死锁               ∂L/∂g = +3.95（非零）；g 更新一步后 ∂L/∂E1 解锁   ✅
⑤ 效率账                   见下
⑥ 自主选拼                 200 输入两两 Jaccard = 0.009，用到 381/384 个忆点   ✅
```

### 第④条特别重要：修掉了 v7 那个坑

v7 失败是因为 θ 和门互相把梯度归零（死锁）。这里：

- `gate` 初始化为 0，但 `E1/E2` 是**随机**的 ⇒ `∂L/∂g ≠ 0`，g 立刻能学
- g 一更新，`E1/E2` 的梯度随即解锁

实测 `∂L/∂g = +3.948`（非零），`g=1e-3` 后 `∂L/∂E1 = -2.57e-05`（已解锁）。**不是永久死锁。**

## 四、效率账（d=128）

| 配置 | 总参数（忆点库容量） | 每 token FLOPs |
|---|---|---|
| dense FFN (ff=4d) | 131,072 | 262,144 |
| **拼 k=4, h_cell=32** | **3,145,728 (24× dense)** | 81,920 (**0.31×**) |
| **拼 k=8, h_cell=32** | **3,145,728 (24× dense)** | 147,456 (**0.56×**) |
| 拼 k=16, h_cell=32 | 3,145,728 (24× dense) | 278,528 (1.06×) |

**同算力下总容量是 dense 的 24 倍** —— 这才是 MoE 的价值主张，旧版拿不到（拼 k 个容量不增长，算力却照付）。

默认配置（d=128, L=4, n=384, h_cell=32, k=8, n_cells=1）：

```
参数量      ≈ 12.9M（与 v3@256 的 11.97M 同量级，可直接对比）
拼后宽度     8×32 + 32 = 288
每 token FLOPs/层  147,456  = dense@256 的 0.14 倍
```

## 五、显存安全阀（重要，别忽略）

`E1[topi]` 的形状是 `[C, k, d, h_cell]`，C = chunk 数。

- `chunk=1` → C = B×T，`E1[topi]` 会炸显存
- `chunk=32` → C = B×T/32，可控（默认）

所以 `train_v8.py` 默认 `--chunk 32`：同一段文本共用一组专家。**这本来就是原设计的语义**（`SnowflakeB` 默认 `chunk_size=32`，只是 LMV4 传了 1）。

## 七、必须诚实说明的三点

1. **自检证明的是「能表示」，不是「学得会」。** 数学上拼 k 个 = k 倍容量已证；梯度下降能不能找到，只有训练能说。这个坑（挂谷）已经踩过一次。

2. **总参数变大了（12.9M vs v3 的 5.64M）。** 这不是退步 —— MoE 的正确对比维度是**每 token FLOPs**（0.14× dense@256），不是总参数。但如果只看参数量会显得难看，写论文时口径要说清。

3. **这仍然是小规模（25MB / 3000 步）。** MoE 的价值主张在大规模才完全兑现，这个规模假设从来没被测过。
