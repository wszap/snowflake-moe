# 翻转式下水道塞（Flip-Trap）

把老式下水道翻转塞做成一个神经网络模块。四个维度各自对应装置的一个部件。

## 四维对应

| 维度 | 物理部件 | 算法实现 |
|---|---|---|
| **一维** | 两个支点 | 轴 `u`，可移动，但**永远在对面、过中心** |
| **二维** | 边缘那圈黑橡胶（密封圈） | 软门槛，分选"细碎的"和"打结的" |
| **三维** | 厚度 | 兜住扣下来的团（carry 累积容量） |
| **四维** | 翻转动作本身 | 翻转角 `α`，跨位置/跨 chunk 传递 |

**密封圈在厚度中心**（赤道面）——这一句是关键：翻转 180° 后密封圈位置不变，所以它**翻到任何角度都在执行分选**。对应到算法里，`s ⊥ u` 且 `s` 位于垂直子空间的赤道位置。

## 工作流

```
输入 x（本步新产生的信息，如细胞器输出 delta）
  │
  ├─① 轴 u 分解 ──── x_par（沿轴）  → 一动不动，支点稳住，主信息永不丢失
  │                  x_perp（垂直） → 交给翻转片
  │
  ├─② 密封圈分选 ─── tangle = seal_net(x_perp)
  │                  gate = sigmoid(tangle / temp)     ← 软门槛，橡胶有弹性
  │                  trapped = gate · x_perp   打结的团，扣下
  │                  free    = (1-gate) · x_perp  细碎的，照常流走
  │
  ├─③ 厚度兜住 ───── carry = thickness·carry + mean(trapped)
  │
  ├─④ 翻转角 α ───── free 在 (s,e) 平面内等距旋转
  │                  α 与 carry 一起传到下游
  │
  └─⑤ B 方案 ─────── 兜住的团注入下游（送到下一段集中处理），不是丢弃
```

## 由结构保证、而非靠正则化

这四条不是"调参调出来的"，是数学上必然成立：

| 性质 | 保证方式 |
|---|---|
| 平行分量严格不变 | 恒等通道，`x_par` 从不参与任何变换 |
| 翻转是等距旋转 | `cos²+sin²=1`，只改方向不改大小 → 数值不跑飞 |
| 两个支点恒在对面 | 轴由 `±u` 定义，结构性对称 |
| 加了不会变差 | `carry_proj` / `alpha_net` / `axis_in` 零初始化 → 起步退化为恒等 |

## 自检结果（17/17）

`python3 verify_flipper_math.py`

```
① 零初始化 → 严格恒等        max|y-x| = 4.44e-16
   出厂配置(bias=-8) 软退化    相对偏差 = 1.11e-07
② 平行分量不变               相对误差 = 2.72e-09
③ u⊥s / u⊥e / s⊥e / ||u||=1 全部 < 5e-10
④ 等距旋转（4 档 α 增益）     ratio = 0.99999989
⑤ carry 跨段传递成功         团保留而非清零
⑥ 512 步 ×10 放大无溢出，200 段连续传递 carry 有界
```

修复记录（自检抓到的真 bug）：
- `gate = sigmoid(0)` = **0.5**，导致零初始化时垂直分量被砍掉一半（范数比 0.51），
  违反"加了不会变差"。→ 门槛 bias 默认 `-8.0`，起步 gate ≈ 3e-4。

## 监控它是否真在工作

```bash
grep -oE "gate_mean[^,]*|carry_norm[^,]*|alpha_mean[^,]*" flipper_full.log | head
```

- `gate_mean` 长期 ≈ 0 → 密封圈没扣任何东西，模块没起作用
- `carry_norm` 持续增长不收敛 → 厚度（衰减率 0.9）不够，调小 `thickness`
- `par_frac` 接近 1 → 几乎全是平行分量，翻转片没活干

## 已知局限（诚实版）

1. **翻转是等距的**——只改方向不改大小。它不能放大或衰减信息，缩放仍要靠细胞器。
2. **"打结"的检测信号是我选的**（`seal_net(x_perp)`）。它是否真能识别长距离依赖/歧义，
   没有理论保证，只能看实验。
3. **能否缩小与 dense 的差距，未知。** 数学漂亮 ≠ 效果好，必须跑出来才算数。
4. 前面已确认的瓶颈是**有效秩被 `rank=4` 锁死**。翻转塞**不提升秩**
   （等距变换不改变秩）——它治的是"信息流跨 chunk 断开"，治不了"单次改造能力弱"。
   这两个是不同的问题。
