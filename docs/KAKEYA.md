# 挂谷翻转塞（Kakeya Flipper）

> 把「翻转式下水道塞」做成多轴 Householder 反射，
> 用来解开「细胞器输出有效秩被 `rank=4` 锁死」这个病根。

---

## 一、物理装置 → 算法（四维）

| 维度 | 物理 | 算法 |
|---|---|---|
| **一维** | 两个支点（可移动，永远在对面） | 翻转轴 `u`，从忆点库检索；`±u` 结构性对称 |
| **二维** | 边缘那圈黑橡胶（密封圈，在厚度中心） | 分选门槛（本版由检索分数隐式承担） |
| **三维** | 厚度 | 兜住能力（由 `α` 的幅度承担） |
| **四维** | 翻转这个动作 | 翻转角 `α ∈ [-1, 1]`，0 = 不翻，1 = 完全翻面 |

密封圈在**厚度中心（赤道）**是关键：翻 180° 后它位置不变，
所以**翻到任何角度都在执行分选**。

---

## 二、数学内核

一次完全翻转 = 一个 Householder 反射：

```
y = x − 2 (x·u) u  =  (I − 2uuᵀ) x
```

性质（都由结构保证，不靠正则化）：

- **正交**：`HᵀH = I`（等距，只改方向不改大小 → 数值不跑飞）
- **自逆**：`H² = I`（翻两次回到原样 → 天然可逆，可当记忆单元）
- **支点对称**：`±u` 由结构保证永远在对面

**Cartan–Dieudonné 定理**：d 维空间中任意正交变换，
可分解为**至多 d 个反射的复合**。

⇒ **K = d 个翻转塞串联，可表示任意正交变换 = 满秩 d。**

这不是类比，是严格定理。自检已用构造性算法验证：
d=8/32/128 时，分别用 7/31/127 个反射精确还原随机正交矩阵，
残差 1e-15 量级（`verify_kakeya_math.py` 第【3】条）。

---

## 三、★ 最关键的一点：秩来自「检索」，不是来自「反射」

这一条如果不理解，整个模块会被误判。

**正交变换不改变秩。**

若 K 个轴对所有 token 都相同（固定轴矩阵 `M`）：

```
rank(X Mᵀ) = rank(X)      ← 秩一点没变
```

秩的提升**只能**来自「轴随输入变化」：不同 token 检索到不同的轴，
于是低秩的 delta 被送到**彼此不同的方向**，整体覆盖的维度才扩大。

### 自检实测（d=128，输入 delta 的秩 = 4）

| 模式 | 结果 |
|---|---|
| 固定轴（所有 token 同一组轴） | rank **4 → 4** |
| 检索轴（每个 token 自己挑） | rank **4 → 128**（满秩） |

**K=8 就够了**，加到 128 也不会更好（秩已经满了）。

```
K=  4   秩 = 114 / 128
K=  8   秩 = 128 / 128   ← 满秩
K= 16   秩 = 128 / 128
K=128   秩 = 128 / 128
```

## 四、与挂谷猜想的关系（必须说清楚，不能夸大）

**诚实定位：挂谷猜想提供的是思想启发，不是数学依据。**

| | 挂谷猜想 | 翻转塞 |
|---|---|---|
| 测度（体积） | 可趋近 **0** | 参数极少（K + d ≈ 136 个） |
| 维数 | 必须是 **n**（满） | 可覆盖全部 **d** 个方向 |

「体积小」与「方向全」并不矛盾——这正是挂谷集合最反直觉的性质。
翻转塞与之同构：**用极少的参数，覆盖所有方向**。

但**真正提供数学保证的是 Cartan–Dieudonné 定理**（第三节），
不是挂谷猜想。挂谷猜想本身（尤其 n≥4）仍是开放问题，
本工作**没有证明、也没有用到**它的任何结论。

一个有趣的巧合：n=3 的挂谷猜想 2025 年刚被证明，n≥4 至今开放；
而本装置恰好是**四维**的。但这只是巧合，不构成数学联系。

## 五、开销（d=128, n_anchors=384）

| | 参数 | FLOPs / token |
|---|---|---|
| 挂谷翻转塞 K=8 | **136** | 104,448（dense 的 **39.8%**） |
| dense FFN (128→512→128) | 131,072 | 262,144 |

参数省 **964×**，FLOPs 省 **2.5×**。

轴本身**复用忆点库**（`organelle_memory`），不新增方向参数——
符合原设计：忆点提供方向，翻转塞只当执行机构。

FLOPs 随 K 增长很慢（检索占大头）：

```
K=  8  →  dense 的 39.8%
K= 32  →  dense 的 46.9%
K=128  →  dense 的 75.0%
```

## 六、零初始化保证（加了不会变差）

```
α 初始化 0        → y = x − 0·(...) = x      严格恒等
对角门初始化 0    → 乘 (1 + tanh(0)) = 1     严格恒等
```

自检实测：零参数时 `max|y − x| = 0.00e+00`（精确为 0）。

⇒ 起步时本模块**完全退化为直通**，第一步 loss 与 v3 完全一致。
无论 K 多大，都不会让模型变差——最坏情况就是学成恒等。

（注：上一版 `flipper.py` 曾因 `sigmoid(0)=0.5` 砍掉一半垂直分量，
违反此保证，已修正。本版从设计上避免了该问题。）

## 八、怎么用

```bash
# 数学自检（先跑这个，10 秒）
python3 verify_kakeya_math.py

# smoke（2 分钟，验证链路）
python train_v6.py --data data_25mb.txt --smoke --L 2 --n-cells 2 --kakeya-k 8

# K 扫描（约 20 分钟）
bash run_kakeya_test.sh 3000
```

**判据**（v3 的 seed 噪声约 ±0.021）：

| K 相对基线 K=0 的 val_loss 提升 | 结论 |
|---|---|
| > 0.021 | ✅ 超出噪声 → 秩确实是瓶颈，翻转塞有效 |
| 0.010 ~ 0.021 | ⚠ 模糊 → 补 seed 确认 |
| < 0.010 | ❌ 噪声内 → 秩不是瓶颈，得重新找原因 |

同时看 **`α` 的绝对值**：如果训练完 `|α| ≈ 0`，
说明模型没学会翻转，秩的提升只是理论可能，没被实际用上。

## 九、已知局限（必须知道）

1. **能表示 ≠ 学得会。** Cartan–Dieudonné 保证"存在这样的分解"，
   没保证梯度下降能找到它。自检的满秩是**理论可达**，不是训练后实测。

2. **top-K 检索不可微。** 轴的**选择**无梯度（只有轴的值和 `α` 有）。
   这是 straight-through 式的近似。

3. **串行 K 次对 GPU 不友好。** FLOPs 少不等于墙上时钟快——
   K 次串行小运算可能比一个大矩阵乘法还慢。只有实测才知道。

4. **正交变换不能缩放。** 已用廉价对角门补上（额外 d 个参数）。
   合起来就是 SVD 的形状：反射给 `U/Vᵀ`，对角门给 `Σ`。

5. **本模块只治「秩」，不治「上下文」。** 上下文问题已由核架解决；
   两者是不同的病。
