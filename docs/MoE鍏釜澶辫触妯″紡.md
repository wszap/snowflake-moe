## 发现 1：软硬分离骗局 —— 熵正常，硬分配已经崩了

### 现象

监控 router 时同时看两个指标：

| 指标 | 值 | 判读 |
|---|---|---|
| `router_ent`（softmax 概率熵） | 正常 | "路由很健康" |
| `org_sum`（硬分配集中度量） | **16.0** | **已坍缩** |

大多数 MoE 论文**只监控前者**。

### 为什么两者会背离

关键在于：**熵是平均量，硬选择是极值量。**

设 N=16 个专家，专家 0 的 logit 恒定比其余高 δ，其余相等：

| δ | p₀(softmax) | router_ent | 归一化熵 | top-1 选中 0 的比例 |
|---|---|---|---|---|
| 0.00 | 0.0625 | 2.7726 | 1.0000 | 6.25% |
| 0.10 | 0.0686 | 2.7723 | **0.9999** | 6.86% |
| 0.50 | 0.0990 | 2.7628 | **0.9965** | 9.90% |
| 1.00 | 0.1534 | 2.7212 | 0.9815 | 15.34% |
| 2.00 | 0.3300 | 2.4485 | 0.8831 | 33.00% |

**看 δ=0.5 这一行**：归一化熵 0.9965 —— 按任何常规阈值这都是"完美均衡"。但专家 0 的硬选择概率是其余专家的 **10 倍**，并且在 argmax / top-k 决策下会**稳定地、每一批次地**吃掉远超份额的 token。

推论：

```
恒定的微小 logit 优势
  ⇒ softmax 熵几乎不动（因为是二阶量）
  ⇒ 但 argmax 是零阶量，100% 响应
```

**数学上**：熵对 logit 扰动的响应是 O(δ²)，argmax 的响应是 O(δ)。所以熵天然对早期坍缩不敏感。

### 给实践者的警告

- **只监控 softmax 熵，必然漏掉硬坍缩。**
- 必须同时监控硬分配量：`top-1 份额`、`max/mean 负载比`、`专家被选中频率的方差`。
- 建议把 `org_sum` 类指标写进训练日志，与 entropy 并排打印。

### 可信度

⚠️ 现象来自本项目观测（`org_sum=16.0`）。**数学机制**（熵 vs 极值的阶数差异）是严格可证的，上表已验算。但"16.0 对应多严重的坍缩"取决于该指标的精确定义，建议读者在自己的代码里重新标定。

## 发现 2：反向蒸馏 —— 好学生被差生拖下水

### 现象

标准蒸馏的假设是"强者教弱者"：teacher 更强，student 向 teacher 对齐，双方受益。

在 MoE 里观察到相反的方向：**teacher 被 student 同化，性能下降。**

### 为什么会发生

MoE 的 routing 是**离散决策**，而蒸馏的梯度是**连续的**。这造成一个结构性问题：

```
student 的 routing 分布 → 通过 distill loss 回传 → 影响 teacher 的 logits
```

但 student 的 routing 本身是噪声主导的（尤其在训练早期）。于是：

1. student 的随机 routing 偏好被当作"知识"传给 teacher
2. teacher 为了匹配这些随机偏好，扭曲自己已经收敛的 logits
3. teacher 性能下降

**关键区别**：dense 模型蒸馏时，student 模仿的是 teacher 的**输出分布**，这是平滑且有意义的。MoE 蒸馏时若把 **routing 决策**也纳入模仿对象，传的就是离散噪声。

### 触发条件（推测，待验证）

- student 与 teacher 的专家数不同 ⇒ routing 空间不对齐 ⇒ 更容易反向污染
- distill 权重过高 ⇒ teacher 的 CE loss 被压过 ⇒ 无法抵抗扭曲
- 训练早期就开始 distill ⇒ student routing 最不稳定时污染最强

### 建议

- **不要蒸馏 routing 决策**，只蒸馏最终输出。
- 若要蒸馏 routing，用 stop-gradient 切断 teacher 侧回传。
- 监控 teacher 的独立 val loss，一旦上升立刻停。

### 可信度

⚠️ 单 seed 观测。机制解释是合理的假设，但我没有做消融来确认"是哪一成分的蒸馏导致了污染"。**这是一个反面案例，不是一个已证明的机制。**

## 发现 3：两阶段延迟坍缩 —— 单向 ENT 是"延迟引信"

### 现象

（锁 3.7.2 配置）

```
步数 0 ~ 7400     : 路由均衡，指标平稳
步数 7400+        : 突然坍缩
```

### 机制

单向 ENT（entropy 正则）只在**熵过低**时惩罚。前期它和 CE loss 的梯度方向一致（都要降低 loss），所以被"顺带"压制：

```
前期：CE loss 主导，量级远大于 ENT
     ⇒ ENT 的回推力被淹没，但【持续积累偏好】
后期：CE loss 下降，量级变小
     ⇒ ENT 的相对权重突然上升
     ⇒ 之前积累的偏好一次性爆发
```

这是**正则项权重的时间动态**问题：正则项的绝对强度不变，但相对强度随主 loss 下降而放大。

### 为什么危险

常规做法是"训练前 1000 步看是否稳定，稳定就继续跑"。**这个做法对延迟坍缩完全无效**——前 7400 步的平稳恰恰是坍缩的前兆。

### 建议

- 正则项的相对权重 = `λ_reg / loss_main`，应该**监控这个比值**而非只看 λ。
- 长训练必须做中间检查点，不能只看前 1000 步。
- 考虑让 λ 随训练步数衰减，抵消主 loss 下降带来的相对放大。

### 可信度

⚠️ 单 seed，且 7400 这个数字高度依赖具体配置（lr、λ、数据）。**"两阶段"这个模式本身值得警惕，但具体步数不可外推。**

## 发现 4：可导容量惩罚 vs Token Dropping（最强正结果）

### 现象

| 方法 | 指标 | drop ratio |
|---|---|---|
| 可导容量惩罚 | **0.8955** | 0% |
| Token Dropping | 0.7383 | **79%** |
| **差值 Δ** | **+0.157** | |

### 为什么这是最有价值的发现

这是六个发现里**唯一的正结果**，而且机制清晰：

```
Token Dropping : 79% 的 token 被硬丢弃 ⇒ 训练时只有 21% 的信号参与
可导容量惩罚   : 0 被丢弃，全部参与，只是被软约束
```

**Δ=0.157 的差距，主要就来自那被丢弃的 79%。**

### 统计强度评估（必须做）

当前是**单 seed**。要判断 Δ=0.157 是否显著，需要知道 seed 间标准差：

| seed 间 SD | Cohen's d_z | 需要 seed 数（α=0.05, power=0.8） |
|---|---|---|
| 0.02 | 7.85 | 2 |
| 0.05 | 3.14 | 2 |
| 0.08 | 1.96 | 3 |
| 0.10 | 1.57 | 4 |
| 0.157 | 1.00 | 8 |
| 0.20 | 0.78 | 13 |

**结论**：

- 若 seed 间 SD ≤ 0.05 ⇒ 3~4 个 seed 足够
- 若 SD ≈ 0.15 ⇒ 需要 ~10 个 seed
- SD > 0.2 ⇒ 单 seed 完全不可信

**当前状态：只能作为方向性证据，不能作为结论。**

### 建议补的实验（能把因果链坐实）

扫 drop ratio ∈ {30%, 50%, 79%, 90%}：

```
若 Δ 随 drop ratio 单调递增  ⇒ 因果链清晰，证据极强
若 Δ 与 drop ratio 无关      ⇒ 优势来自别处，需重新归因
```

这个扫描很便宜（复用同一份 checkpoint），**强烈建议做**。

### 可信度

⚠️ 单 seed。方向明确，但**统计强度未知**。上表给出了需要多少 seed 才能定论。

## 发现 5：任务复杂度决定"拼专家"是否必要 ✅

### 现象

同一个架构，在不同难度任务上表现完全不同：

| 任务 | eff（有效器官数） | 行为 |
|---|---|---|
| 合成任务（8 簇，每簇一个真专家） | **4.00** | 退化 one-hot |
| 字符级 LM（TinyStories, N=384） | **18** | 真组合 |
| 带约束的对照 | 31.3 | 偏平均 |

（`eff = 1/Σw²`，即"每样本真正用到几个器官"，跨 N 可比）

### 关键推论

**在简单任务上，one-hot 就是最优解。模型没做错，是任务没逼它。**

合成任务里 8 个簇、每簇对应一个真专家，最优策略显然是直接挑一个。模型一眼看穿，1 个 epoch 就到最优解。**这不是架构缺陷。**

字符级 LM 上，上下文依赖足够复杂，单个器官容量不足 ⇒ 模型**自发**使用约 18 个器官。

### 最有价值的一点

**`eff=18` 是在 `min_eff=0`（完全无约束）下达到的，而且 loss 更低：**

| 配置 | loss | eff |
|---|---|---|
| 带约束 min_eff=8 | 1.784 | 31.3 |
| **无约束 min_eff=0** | **1.779** | **18** |

不需要任何强制机制，模型自发组合，且效果最好。

### 这解释了什么

> 很多人试 MoE 在小任务上"没效果"——因为小任务根本不需要组合。

**判据**：先用单器官 baseline 测一下。如果单器官就能解决，MoE 不会有收益。

### 可信度

✅ **这一条有完整数据支撑**（3000 步训练，eff 收敛曲线完整，loss 对照）。是六个发现里最扎实的。

## 发现 6：帐篷函数的梯度死区 ✅

### 现象

用帐篷函数（两个 relu 相乘）做带通约束：

```python
tent(cos) = relu(cos - lo) * relu(hi - cos)      # lo=0.3, hi=0.8
```

在 cos > hi 后**值和梯度同时恒为 0**。

### 数值验证

| cos | 帐篷值 | 帐篷梯度 | 平方值 | 平方梯度 |
|---|---|---|---|---|
| 0.50 | 0.06000 | 0.10000 | 0 | 0 |
| 0.70 | 0.04000 | -0.30000 | 0 | 0 |
| 0.75 | 0.02250 | -0.40000 | 0 | 0 |
| 0.80 | 0.00000 | -0.25000 | 0 | 0 |
| **0.85** | **0.00000** | **0.00000** | **0.00250** | **0.10000** |
| **0.90** | **0.00000** | **0.00000** | **0.01000** | **0.20000** |
| **1.00** | **0.00000** | **0.00000** | **0.04000** | **0.40000** |

对比平方铰链 `sq(cos) = relu(cos - hi)²`：

```
帐篷 : cos>0.8 后 值=0 且 梯度=0  ⇒ 器官一旦趋同，【永久死亡】，无法挽回
平方 : cos>0.8 后 值>0 且 梯度=2(cos-0.8) 线性增长  ⇒ 越趋同，回推力越大
```

### 为什么这是设计分水岭

这是**约束函数形式**的根本区别：

| 形式 | 语义 | 带外行为 |
|---|---|---|
| **帐篷 / 乘积** `relu(x-a)·relu(b-x)` | 带内**奖励** | 带外梯度死区 ⇒ 不可逆 |
| **平方铰链** `relu(x-a)²` | 带外**惩罚** | 梯度随偏离线性增长 ⇒ 可逆 |

**这个区别是数学事实，不是调参问题。** 帐篷函数只能用于"器官还没趋同"的预防，一旦趋同就再也拉不回来。

### 建议

任何"希望参数保持在某区间内"的约束，**必须用平方形式，不要用乘积形式**。

```python
# ❌ 帐篷：带外梯度死区
loss = relu(cos - 0.3) * relu(0.8 - cos)

# ✅ 平方：双侧都有回复力
loss = relu(cos - 0.8)**2 + relu(0.3 - cos)**2
```

双侧平方铰链的梯度方向（已验证）：

| cos | d/dcos | 谁在管 |
|---|---|---|
| 0.0 | **−0.600** | 下侧推 cos 上升 |
| 0.3~0.8 | **0** | 带内不管，不干扰已学分工 |
| 1.0 | **+0.400** | 上侧推 cos 下降 |

### 可信度

✅ **纯数学事实，已数值验证。** 这一条不需要任何实验支撑。

## 局限与诚实的说明

1. **发现 1/2/3/4 均为单 seed。** 我给出了发现 4 需要的 seed 数量表，其余同理。**在补 seed 之前，请把它们当作"值得警惕的现象"而非"已证明的结论"。**

2. **发现 2 和 3 的机制解释是假设。** 我没有做消融来确认因果。它们的价值在于"提醒别人注意这个方向"。

3. **发现 5 的数据来自字符级 LM（vocab=98）。** 词级任务上的行为可能不同，需要单独验证。

4. **发现 6 与具体实现无关。** 它是 relu 乘积形式的固有性质，任何用帐篷函数做带通约束的代码都会踩到。
