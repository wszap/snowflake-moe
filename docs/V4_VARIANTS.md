# Snowflake v4 变体实验：在「拼专家」基础上系统尝试各种方法

## 一、诊断：65% 差距的真正主因是「有效秩」

跑通核架之后，v3 与 dense 的对比变成**公平赛道**（两边每层都有因果注意力 + 残差），
差距仍有 65%（loss 1.7066 vs 1.035）。问题不在上下文，在**每个 token 的变换能力**。

### 有效秩的量化

| | 结构 | 每 token 变换的有效秩 |
|---|---|---|
| Snowflake 细胞器 | rank=4 低秩 × 激活约 2.8 个 | **≈ 11** |
| dense FFN (d=128) | W1: 128→512→128，全秩 | **128** |

**低了约一个数量级。**

细胞器把参数省在了「384 个可组合的候选」上，但每个候选只有 rank=4，
且每次只激活约 2.8 个 —— 合起来对单个 token 施加的仍是一个**极低秩的扰动**。
这是「用参数量换组合空间」的直接代价。

### 次要因素

- `d=128` vs dense 的 `d=288`：残差流宽度只有一半多
- `temp=5.0`：softmax 偏尖锐，eff 只有约 2.8

## 三、实验 B：v4 架构变体（新代码，保留拼专家核心）

核心完全不变：忆点 384、细胞器低秩因子、**无 router 的自发分工**、核架、忆点互相关联。
只在周边加三项改进，`--variant` 逗号分隔可组合。

### B1 `shared` —— 共享全秩专家

每层加一个 `d → mult*d → d` 的全秩 MLP，**每个 token 都经过**。

作用：直接把有效秩从 ≈11 拉到全秩。这是 DeepSeekMoE 的 shared-expert 思路，
但在这里尤其关键 —— 因为细胞器路径的秩缺口是数量级的。

代价：mult=4 时约 +0.5M 参数（d=128）。

### B2 `pair` —— 二阶器官协作（创新点）

```
out_pair = (w @ P) ⊙ (w @ Q)        P, Q ∈ R^{384×d}
```

数学上展开即：

```
Σ_i Σ_j w_i w_j (P_i ⊙ Q_j)
```

**这就是器官两两之间的协作项** —— 符合「细胞器不是独立工作、会形成复合体」的直觉。

关键是**复杂度**：直接算 Σ_ij 是 O(n²·d)，而 `(w@P)⊙(w@Q)` 只要 **O(n·d)**。
用低秩分解拿到了二阶交互，代价和一次线性投影相当。

`pair_proj` 用**零初始化**：训练开始时该项贡献恰为 0，退化成 v3 行为，
保证「加了不会变差，只会变好或持平」。

### B3 `gate` —— 细胞门控

原来 4 个 cell 是 `sum(outs)/len(outs)` 硬平均。改成 `softmax(logits)` 可学习加权，
让 4 个细胞组自然分化（比如一组管局部、一组管语义）。

### B4 `all` —— 三者全开

```bash
cd /mnt/workspace/snowflake-moe/v2_compositional
bash run_variants.sh 2>&1 | tee variants.log
```

**约 20 分钟**（5 个 run）。

## 四、因果性保证

三项改进**全部是 per-token 操作**，不引入任何跨 token 信息流：

- `shared`：逐 token MLP
- `pair`：只用当前 token 自己的 wiring
- `gate`：逐层常数权重

因此 `leak_check` 应仍为 0.00e+00。**若自检失败，说明有 bug，数字作废。**

## 五、判定标准

| 结果 | 结论 |
|---|---|
| rank32/64 明显优于 rank4 | 有效秩假设成立 → 继续加秩/加共享专家 |
| `shared` 明显优于 `base` | 秩缺口确认 → 这是主线方向 |
| `pair` 优于 `base` | 二阶协作有价值 → **独创机制，可写论文** |
| 三者都无改善 | 瓶颈不在 FFN 表达能力 → 需重做诊断 |

**最值得期待的是 `pair`** —— 它不靠堆参数，而是靠机制创新提高有效秩，
且天然契合「细胞器协作」的设计思想。
