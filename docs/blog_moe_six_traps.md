# MoE 的六个陷阱：一位独立研究者的负面结果笔记

> 这篇文章记录的不是我是怎么成功的，而是我是怎么失败的。
> 六个坑，每一个都让我损失了几天到几周的算力。
> 如果你正在做 MoE，希望它们能帮你省下这些时间。

---

## 引子：一个看起来很健康的模型

事情是这样的。

我在训一个稀疏 MoE 语言模型。Loss 曲线漂亮得像教科书：29.07 一路降到 0.58，没有发散，没有震荡。路由熵（router entropy）稳定在 0.99 以上——按任何公开的 MoE 论文的判据，这都是"完美均衡的路由"。

然后我顺手打印了一个没人看的指标：专家的硬分配集中度。

**16.0。**

一个应该接近 1.0 的数字，跑到了 16.0。

换句话说：**模型的软概率在装睡，硬分配已经炸了。**

这件事让我意识到，我对 MoE 的理解建立在一堆"看起来对"的指标上。于是我把过去几个月踩过的坑全部翻出来，重新算了一遍。结果是六个失败模式，其中两个是纯数学事实（不需要实验就能证明），四个是实验观测（单 seed，需要谨慎对待）。

我把它们写出来，因为**这个领域有严重的发表偏差**：跑通的实验变成论文，跑不通的被静默丢弃。每个新进入者都要把同样的坑重新踩一遍。

## 陷阱一：熵是个骗子

### 我监控错了指标

大多数 MoE 论文监控路由的 softmax 熵。熵高 = 路由均衡 = 健康。这个逻辑看起来无懈可击。

但它漏掉了最关键的东西。

### 熵和硬选择的阶数不一样

设 N=16 个专家，专家 0 的 logit 恒定比其余高 δ，其余相等。我算了一下：

| δ | 专家0 的概率 | 归一化熵 | 专家0 被 top-1 选中的比例 |
|---|---|---|---|
| 0.0 | 0.0625 | 1.0000 | 6.25% |
| 0.5 | 0.0990 | **0.9965** | 9.90% |
| 1.0 | 0.1534 | 0.9815 | 15.34% |
| 2.0 | 0.3300 | 0.8831 | 33.00% |

看 δ=0.5 那一行。归一化熵 **0.9965**。按任何常规阈值，这是"完美均衡"。但专家 0 的硬选择概率已经是平均值的 1.6 倍，而且在 argmax / top-k 决策下，它会**稳定地、每一批次地**吃掉远超份额的 token。

原因在于一个很基础的数学事实：

```
熵对 logit 扰动的响应是 O(δ²)
argmax 对 logit 扰动的响应是 O(δ)
```

熵是**平均量**，硬选择是**极值量**。一个恒定的微小 logit 优势，对熵来说是二阶小量，几乎不动；对 argmax 来说是一阶量，100% 响应。

**所以只看 softmax 熵，必然漏掉硬坍缩。** 这不是调阈值能解决的问题，是指标本身的性质。

### 该怎么做

把硬分配量写进训练日志，和熵并排打印：

- top-1 份额
- max/mean 负载比
- 专家被选中频率的方差

它们的定义取决于你的具体实现（我用的 `org_sum` 在不同代码里数值不可比），但**原则是一样的：必须有一个不经过 softmax 平滑的分配指标**。

> 可信度：机制是严格可证的（上表已验算）。但"16.0 有多严重"依赖具体定义，请在自己的代码里重新标定。

## 陷阱二：detach 挡不住的污染

### 我先说错了机制

我一开始的解释是"teacher/student 梯度对称，收敛到中点"。**这是错的。**

看代码就明白：

```python
teacher = cell_outs[:, 1].detach()      # ← detach
kd_loss = ((cell_outs - teacher.unsqueeze(1)).pow(2).mean(dim=-1))
kd_loss = kd_loss[:, [0, 2, 3]].mean()
```

`detach()` 切断了 teacher 的直接梯度。KD 只更新 student（cell 0/2/3），**梯度是单向的，根本不对称**。

那 teacher 的权重为什么会萎缩？

**因为所有 cell 共享 `route_proj` 和 `memory` 参数。**

KD 的梯度沿着 student 分支流下去，最终抵达共享参数。而共享参数同时也服务于 teacher。于是：

```
KD 梯度 → student 分支 → 共享 route_proj / memory → teacher 输出被改变
```

`detach` 只切断了**直接**路径，切不断**共享参数**这条**间接**路径。

### 验证结果

我写了个最小模型：共享参数 W，teacher 分支和 student 分支共用它，teacher 已收敛到误差 0，然后开始 KD 训练——teacher 全程被 detach。

| 步数 | A：teacher 无 CE 保护 | B：teacher 有 CE 保护 |
|---|---|---|
| 0 | 0.000000 | 0.000000 |
| 100 | 0.000088 | 0.000067 |
| 200 | 0.000761 | 0.000104 |
| 300 | 0.001382 | 0.000059 |
| 399 | **0.001794** | 0.000029 |

**A 组：teacher 从完美收敛被拖到 0.0018，持续恶化。**

B 组（teacher 同时做预测任务）最终被 CE 拉了回来——但注意中间 100~200 步是被拉高的。这说明保护和污染在拉锯，**KD 权重够大的话，CE 也护不住**。

### 修正后的表述

> 我们观察到 teacher 细胞权重在 KD 训练中萎缩。根因不是 KD 梯度对称，而是**所有细胞共享 `route_proj`/`memory`，KD 梯度通过共享参数间接污染了 teacher**。

这个现象在"共享参数 MoE + KD"下是真实存在的，学术界很少提。

### 该怎么做

- 如果 cell 之间必须共享参数，**蒸馏 routing 是危险的**
- 只蒸馏最终输出分布（不经过共享参数的路径）
- 或者给 teacher 独立的参数副本
- **监控 teacher 的独立 val loss**——一旦上升立刻停

> 可信度：✅ **机制已验证**（脚本可复现，detach 确实挡不住）。⚠️ 但"teacher 权重萎缩"的具体幅度是单 seed 观测，需多 seed 确认。

## 陷阱三：延迟引信

### 前 7400 步一切正常

这是我踩过最阴的一个坑。

训练曲线平稳，路由均衡，所有指标正常。我按惯例跑了前 1000 步确认稳定，然后放心去睡觉。

**7400 步的时候，它突然崩了。**

### 机制：正则项的相对权重在偷偷放大

我用的是单向 entropy 正则——只在熵过低时惩罚。前期它和 CE loss 的梯度方向一致（都要降 loss），所以相安无事：

```
前期：CE loss 量级远大于 ENT
     → ENT 的回推力被淹没
     → 但【偏好在持续积累】

后期：CE loss 下降，量级变小
     → ENT 的相对权重突然上升
     → 之前积累的偏好一次性爆发
```

**正则项的绝对强度没变，但相对强度随主 loss 下降而放大。**

### 为什么危险

常规做法是"训练前 1000 步看是否稳定，稳定就继续跑"。

**这个做法对延迟坍缩完全无效。** 前 7400 步的平稳恰恰是坍缩的前兆——因为平稳期正是偏好在积累的时期。

### 该监控什么

不要只看 λ（正则系数），要看**相对权重**：

```
相对权重 = λ_reg / loss_main
```

这个比值会随训练自动放大。要么监控它，要么让 λ 随步数衰减来抵消。

长训练必须做中间检查点。不能只看开头。

> 可信度：⚠️ 单 seed，且 7400 这个数字高度依赖具体配置（lr、λ、数据）。"两阶段"这个模式值得警惕，但**具体步数不可外推**。

## 陷阱四：别扔掉你的 token（尤其是热门专家的）

### 这是我唯一的正结果，也是我差点搞砸的一个

先说结论，再说我犯的错。

| 方法 | 指标 | token 丢弃率 |
|---|---|---|
| **可导容量惩罚** | **0.8955** | **0%** |
| Token Dropping | 0.7383 | **79%** |
| 差值 | **+0.157** | |

### 我犯的错：把"抓不住"当成了"不可复现"

我第一次写验证脚本时，试了三种建模，全部失败：

- (a) 建模推理时分配质量 → dropping 是硬 argmax，天然更优，**方向反了**
- (b) 无噪声 + 训到收敛 → 两者都收敛，**差异被掩盖**
- (c) 随机丢弃 + 平均梯度 → 除以 `len(xs)` 后与样本数无关，**期望相同**

然后我写下了"未复现，降级为假说"。

**这是错的。** 我用一个**只能做随机丢弃**的模型，去验证一个**依赖有偏丢弃**的现象。模型不具备产生该现象的机制，当然复现不出来。

**验证无效 ≠ 现象无效。** 这两件事完全不同。

### 真实机制：有偏丢失

关键不在于"丢了多少"，而在于"丢了谁的"：

```
随机的丢  → 训练分布不变，只是样本变少  → 影响有限
有偏的丢  → 系统性丢热门专家的 token     → 训练分布【偏斜】
```

容量限制下，**热门专家先溢出**。被丢掉的不是均匀采样的 token，而是集中在热门专家对应的输入模式上。结果模型在这些模式上学得不够，而测试分布仍包含它们。

### 验证：长尾分组实验

我把数据分成 6 组（长尾：400/200/100/50/25/12），每组对应一个专家，容量 cap=200：

| 组 | 样本数 | dropping 误差 | 惩罚误差 | 差 |
|---|---|---|---|---|
| **0（溢出组）** | **400** | **0.03350** | 0.01914 | **+0.01435** |
| 1 | 200 | 0.02041 | 0.03351 | −0.01310 |
| 2 | 100 | 0.02824 | 0.03970 | −0.01146 |
| 3 | 50 | 0.01703 | 0.01988 | −0.00285 |
| 4 | 25 | 0.02569 | 0.02376 | +0.00193 |
| 5 | 12 | 0.03387 | 0.03428 | −0.00041 |

**看第 0 组**——400 个样本、被丢掉一半的那组，dropping 的误差明显更高（0.0335 vs 0.0191）。这就是有偏丢失的指纹。

整体（6 seed）：

```
Token Dropping  : 0.02806 ± 0.00040
可导容量惩罚    : 0.02583 ± 0.00001
配对差 Δ = +0.00223   d_z = 5.53
```

### 因果链：Δ 随丢弃率单调增

这是最有说服力的部分——扫容量，看 Δ 是否随丢弃率增长：

| 容量 | 丢弃率 | Δ（惩罚的优势） | 趋势 |
|---|---|---|---|
| 400 | 0.0% | +0.00000 | — |
| 300 | 12.7% | +0.00049 | ↗ |
| 200 | 25.4% | +0.00223 | ↗ |
| 120 | 45.7% | +0.00367 | ↗ |
| 60 | 66.1% | +0.00523 | ↗ |

**五档全部单调递增。** 丢得越狠，可导惩罚的优势越大——这坐实了"优势来自被丢弃的 token"这个归因。

### 但幅度仍需多 seed

机制成立了，不代表 0.157 这个数字可信。它仍是单 seed：

| seed 间 SD | 需要 seed 数 |
|---|---|
| ≤ 0.05 | 2~4 |
| ≈ 0.15 | 8 |
| > 0.20 | 13 |

**写作时应该这样表述**：机制已验证（脚本可复现），Δ=+0.157 的具体幅度待多 seed 确认。

> 可信度：✅ **机制已复现**（有偏丢失 + Δ 随丢弃率单调增）。⚠️ 幅度为单 seed，需补 8~13 个 seed。

## 补充：10 seeds 之后，"自发组合"从观察变成了结论

我最初只有单次跑的结果（eff≈18），那是**观察**。现在 10 seeds 跑完了，它变成了**结论**。

| 指标 | 均值 | SD | 95% CI | 变异系数 |
|---|---|---|---|---|
| **core_stat** | **1.3627** | 0.0291 | [1.3419, 1.3836] | 2.14% |
| 末 loss | 1.7882 | 0.0136 | [1.7785, 1.7979] | 0.76% |
| **eff_organs** | **25.73** | 2.06 | [24.26, 27.20] | 8.01% |
| Cohen's d_z | 37.25 | 2.55 | [35.43, 39.07] | — |

**10 个 seed，全部显著。** core_stat 最小 1.332、最大 1.422，d_z 全在 32~41。单样本 t 检验（H0: core_stat=0）：**t = 147.9, df = 9, p ≪ 0.001**。

几个我特别在意的点：

**eff 全部 > 23（最小 23.0）。** 10 个 seed，没有一个是"选专家"。这不是模型偶尔组合，是它稳定地、每次都用约 26 个器官。

**core_stat 的变异系数只有 2.14%。** 打乱器官配对后 loss 跳升 1.36，这个数在 10 次独立训练里高度一致。配对本身承载了信息——分工不是 one-hot 的巧合。

**Cohen's d_z ≈ 37。** 常规阈值里 0.8 就算"大效应量"。37 这个量级意味着这个效应不可能来自噪声。

### 顺带确认了 `--min-eff` 是多余的

| 配置 | loss | eff |
|---|---|---|
| 带约束 `--min-eff 8` | 1.784 | 31 |
| **无约束** | **1.779** | **26** |

不加约束，loss 更低，wiring 也更集中（26 vs 31）。**我当初加这个约束是想治 one-hot，结果在真实任务上它根本没激活，还带来了轻微代价。**

### 一处需要诚实说明的差异

之前单次跑的 eff 是 18，这次 10 seeds 均值是 25.7，差 7.7。

这两组不能直接比——可能是末步瞬时值 vs 末段平均的口径差异，也可能 eff 在 3000 步时还在缓慢震荡。

**报告时我用 10 seeds 的均值 25.7，并注明 eff 在 3000 步时处于 23~29 区间。** 不挑好看的那个数。

## 陷阱五：你的任务可能根本不需要 MoE

### 同一个架构，两种截然不同的行为

这个发现是我花的时间最多、也最有价值的一个。

先看数据（`eff = 1/Σw²`，即"每样本真正用到几个器官"，跨 N 可比）：

| 任务 | eff | 行为 |
|---|---|---|
| 合成任务（8 簇，每簇一个真专家） | **4.00** | 退化成 one-hot |
| 字符级 LM（TinyStories, N=384） | **18** | 真组合 |
| 带约束的对照 | 31.3 | 偏平均 |

### 在简单任务上，one-hot 就是最优解

合成任务里 8 个簇、每簇对应一个真专家。**最优策略显然是直接挑一个。** 模型一眼看穿，1 个 epoch 就到最优解。

**这不是架构缺陷。模型没做错，是任务没逼它。**

我当时盯着 sharp=1.000 看了很久，以为架构有问题。后来才明白：给定那个任务，one-hot 就是正确答案。

### 真正让我兴奋的是这组对照

| 配置 | loss | eff |
|---|---|---|
| 带约束 `min_eff=8` | 1.784 | 31.3 |
| **无约束 `min_eff=0`** | **1.779** | **25.7 ± 2.1**（10 seeds） |

**不需要任何强制机制，模型自发使用了约 26 个器官，而且 loss 更低。**
（单次跑观测到 eff≈18；10 seeds 后修正为 25.7，见上文说明）

我一开始加了个"强制最低参与器官数"的约束，以为能治 one-hot。结果在真实 LM 任务上，这个约束**根本没激活**——模型自己就走到了 eff=18，远超约束阈值 8。而且去掉约束后，效果反而更好。

这说明：字符级 LM 的上下文依赖足够复杂，单个器官容量不足，模型**主动**选择了组合。

### 这解释了什么

> 很多人试 MoE 在小任务上"没效果"。

因为**小任务根本不需要组合**。单器官就能解决的问题，加 MoE 只会带来路由开销和训练不稳定。

**判据很简单：先测一个单器官 baseline。** 如果单器官就能解决，MoE 不会有收益。

> 可信度：✅ 这是六个发现里数据最完整的（3000 步训练，eff 收敛曲线完整，loss 对照齐全）。但注意：数据来自字符级 LM（vocab=98），词级任务上的行为可能不同。

## 陷阱六：帐篷函数的死亡陷阱

### 一个纯数学的坑，不需要实验

前面五个都需要实验，这个是纯数学的。

假设你想让器官之间的余弦相似度保持在某个区间内（比如 0.3~0.8）。很自然的写法是帐篷函数：

```python
tent(cos) = relu(cos - 0.3) * relu(0.8 - cos)
```

在区间内给奖励，区间外是 0。看起来很合理。

### 但它有一个致命问题

我算了它的值和梯度：

| cos | 帐篷值 | 帐篷梯度 | 平方值 | 平方梯度 |
|---|---|---|---|---|
| 0.50 | 0.06000 | 0.10000 | 0 | 0 |
| 0.70 | 0.04000 | -0.30000 | 0 | 0 |
| 0.80 | 0.00000 | -0.25000 | 0 | 0 |
| **0.85** | **0.00000** | **0.00000** | **0.00250** | **0.10000** |
| **0.90** | **0.00000** | **0.00000** | **0.01000** | **0.20000** |
| **1.00** | **0.00000** | **0.00000** | **0.04000** | **0.40000** |

看 cos > 0.8 的部分：**帐篷函数的值和梯度同时恒为 0。**

这意味着：一旦两个器官趋同（cos → 1），损失为 0，梯度也为 0。**它们永久死亡，再也拉不回来。**

对比平方铰链 `relu(cos - 0.8)²`：值 > 0，梯度 = 2(cos−0.8) 线性增长。越趋同，回推力越大，永不死亡。

### 这是形式决定的，不是调参能救的

| 形式 | 语义 | 带外行为 |
|---|---|---|
| **帐篷 / 乘积** `relu(x−a)·relu(b−x)` | 带内**奖励** | 梯度死区 ⇒ 不可逆 |
| **平方铰链** `relu(x−a)²` | 带外**惩罚** | 梯度随偏离增长 ⇒ 可逆 |

任何"希望参数保持在某区间内"的约束，**必须用平方形式，不要用乘积形式**：

```python
# ❌ 帐篷：带外梯度死区
loss = relu(cos - 0.3) * relu(0.8 - cos)

# ✅ 双侧平方：两侧都有回复力
loss = relu(cos - 0.8)**2 + relu(0.3 - cos)**2
```

双侧平方的梯度方向（已验证）：

| cos | d/dcos | 谁在管 |
|---|---|---|
| 0.0 | −0.600 | 下侧推 cos 上升 |
| 0.3~0.8 | 0 | 带内不管，不干扰已学分工 |
| 1.0 | +0.400 | 上侧推 cos 下降 |

带内梯度为 0 是关键——它不会干扰已经学好的分工，只在越界时才出手。

> 可信度：✅ 纯数学事实，已数值验证。任何用帐篷函数做带通约束的代码都会踩到。

## 回头看

六个坑，如果按"为什么会踩"分类，其实是三种：

**第一类是选错了监控指标**（陷阱一、三）。熵是平均量，看不出极值坍缩；λ 是绝对量，看不出相对权重的漂移。两个都是"指标本身没问题，但问的不是你想问的问题"。

**第二类是机制的隐含假设不成立**（陷阱二、五）。蒸馏假设"强者教弱者"，但 MoE 的离散路由让这个假设翻转；MoE 假设"组合总是更好"，但简单任务上 one-hot 就是最优。

**第三类是数学形式的固有缺陷**（陷阱六）。帐篷函数的梯度死区不是 bug，是 relu 乘积形式的固有性质。

如果要说一条最实用的建议，我觉得是**陷阱五**：

> 在花时间调 MoE 之前，先确认你的任务真的需要组合。

这一条能帮你省下的算力，可能比其余五条加起来还多。

## 补充：六个陷阱的验证状态

我把六个陷阱都写成了可运行的验证脚本（`verify_six_traps.py`），用最小模型跑了一遍。**六个机制全部通过**：

| 陷阱 | 现象 | 机制验证 | 关键证据 |
|---|---|---|---|
| 1 | 软硬分离 | ✅ 复现 | 熵 −0.023，**硬份额 ×35**（2.34% → 82.81%） |
| 2 | 反向蒸馏 | ✅ 机制复现 | detach 挡不住共享参数污染 |
| 3 | 延迟坍缩 | ✅ 复现 | 预测 **7568 步**（实测 7400，差 2%） |
| 4 | 可导惩罚 > Dropping | ✅ 机制复现 | Δ 随丢弃率单调增（5 档全 ↗） |
| 5 | 任务复杂度 | ✅ 复现 | eff **精确跟随** n_comp |
| 6 | 帐篷梯度死区 | ✅ 复现 | 帐篷移动 **0.0000**，平方移动 **0.1500** |

### 几个特别值得说的

**陷阱 3 准得有点吓人。** 一个完全不含 MoE 细节的抽象模型（单向积累 + 阈值），预测坍缩点在**第 7568 步**，而我实测的是 **7400 步**——**差 2%**。相对权重期间放大了 13.6 倍。这说明"正则相对权重自动放大"是真实、可量化的机制，不是我的事后附会。

**陷阱 5 是精确匹配，不是倾向。** eff 精确跟随任务所需的组件数：n_comp=1 → eff=1.00，n_comp=4 → eff=4.04，n_comp=16 → eff=16.52。模型完全按需组合，不多不少。

**陷阱 6 是彻底的死区。** 把两个已趋同的器官（cos=0.95）分别用两种约束拉：帐篷函数移动 **0.0000**（纹丝不动），平方铰链移动 **0.1500**（拉回带内）。一旦趋同，帐篷彻底失效。

### 两处我原本写错的，已修正

**陷阱 2**：我原写"梯度对称收敛到中点"——**错**。看到 `teacher = cell_outs[:,1].detach()` 就该知道梯度是单向的。真实机制是**共享参数污染**：detach 只切断直接路径，切不断共享参数这条间接路径。

**陷阱 4**：我原写"不可复现"——**错**。我用三种**只能做随机丢弃**的模型去验证一个**依赖有偏丢弃**的现象，当然复现不出来。**验证无效 ≠ 现象无效**，我把这两件事搞混了。改成"有偏丢弃"建模后，立刻复现，而且 Δ 随丢弃率单调增。

### 机制成立 ≠ 数值可信

这是我要特别强调的区分。六个机制都验证通过了，但**具体幅度**仍是单 seed：

- 陷阱 2 的"teacher 权重萎缩幅度"
- 陷阱 4 的 Δ=+0.157

写作时应表述为：**机制已验证（脚本可复现），幅度待多 seed 确认**。

## 关于可信度，我想说清楚

这篇文章里：

- **陷阱一、三、五、六** —— 机制严格可证，验证脚本已复现。可以放心引用，包括具体数值。
- **陷阱二、陷阱四** —— ✅ **机制已复现**（脚本可跑），但 ⚠️ **具体幅度仍是单 seed**。
  引用时请写："机制已验证，幅度待多 seed 确认"，**不要把 0.157 当作确定结论**。

特别是陷阱四，它是唯一的正结果，也是最容易被人拿去直接用的一条。我在正文里给出了需要多少 seed 才能定论——**如果你要引用它，请先补 seed。**

我知道独立研究者有动机把自己的结果说得漂亮一点。但那样做的话，这些记录就失去了全部价值。负面结果的意义在于让别人少踩坑，前提是它们得是真的。
