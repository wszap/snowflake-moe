## 一、审核发现（3 条）

### ⚠️ 发现 1：文档里的恒等式写错了（已修正）

原文 `COMPOSABLE_EXPERT_V8.md` 第 64 行：

```
Σᵢ wᵢ σ(xE1ᵢ)E2ᵢ  ≡  [σ(xE1₁), …, σ(xE1_k)] @ blkdiag(wᵢE2ᵢ)
                                                ^^^^^^^ 错的
```

**独立复算结果**：

```
blkdiag: hcat(32,) @ Wb(32, 256) -> (256,)     ← 目标是 (64,)，形状对不上
vstack : hcat(32,) @ Wv(32, 64)  -> (64,)      max误差 1.665e-16 ✅
```

`blkdiag`（块对角）会拼出 `[k·h_cell, k·d]`，**与目标维度不符**。
正确写法是 **vstack（垂直拼接）** → `[k·h_cell, d]`。

**代码本身是对的**（用的是加权求和，数学上等价于 vstack），
只是文档表述错。已修正并在文档中保留修正记录。

### ✅ 发现 2：核心主张独立复算通过（这是决定性证据）

不复用 `verify_composable_expert.py`，从头用 numpy 算整层 Jacobian 的秩：

| 拼 k 个 | **旧版** rank(J) | **新版** rank(J) | 新版等效宽度 |
|---|---|---|---|
| 1 | 32 | **64** | 64 |
| 2 | 32 | **96** | 96 |
| 4 | 32 | **128** | 160 |
| 8 | **32** | 128 | 288 |
| 16 | **32** | 128 | 544 |
| 32 | **32** | 128 | 1056 |

- **旧版恒为 32，与 k 完全无关** —— 这就是「32 人挤 4 人道」的数学表达：
  拼 1 个和拼 32 个，容量一模一样，算力却照付。
- **新版随 k 线性增长**，到 d=128 封顶。

> 这解释了此前四次失败（rank / clone / 挂谷×2 / pair）：
> 它们都在瓶颈**前后**打转，没有一次碰瓶颈本身。
> 挂谷尤其不可能成功 —— 旋转/反射是等距变换，**秩是旋转不变量**。

### ⚠️ 发现 3：默认配置会让对比不公平（已加安全阀）

- 旧版 `snowflake_v4.py:216` 用 **`chunk_size=1`** → 每 token **独立**自选专家
- v8 `train_v8.py` 默认 **`--chunk 32`** → 32 个 token **共用**一组专家

**v8 在「自主选拼」的精细度上先天吃亏**，直接对比不公平。

改用 chunk=1 的障碍是显存：`E1[topi]` 形状 `[C,k,d,h_cell]`，
chunk=1 时约 **537 MB**，会爆。

**已加自动安全阀**：预估占用超预算时，自动从「一次性 gather」切换为
「逐 slot 计算」，峰值显存降为 **1/k**（537MB → 67MB），chunk=1 即可跑。

```python
need = C * k * d * h_cell * 4 / 1024**2     # MB
if need > mem_budget_mb:                    # 默认 256
    逐 slot（峰值 1/k）
else:
    一次性 gather（更快）
```

两条路径的数值等价性**必须由 GPU 实测**（本地无 torch），
已写好 `verify_v8_lowmem.py`，**上机第一步就跑它**。

## 三、改动了什么（保持你的核心不动）

### 完全没动（你的原创）
- 忆点 `organelle_memory`（384 个，初始化尺度照旧）
- 核架 `connect()`（高斯带通 + 稳态归一化）
- `key = m + c.T @ m`（忆点互相关联）
- `wiring = softmax(x·keyᵀ·temp)` —— **无外部 router，自发分工**
- `min_eff_organs`、`var_norm` 口径（保证指标与旧版可比）

### 改了两处

| | 旧 | 新 |
|---|---|---|
| 细胞器载荷 | `W1_U[n,d,rank]` + **共享** `W1_V[rank,h]` | `E1[n,d,h_cell]`、`E2[n,h_cell,d]`（**各自独立小 FFN**） |
| 合成方式 | 先合参数 → 共享一次 silu | **各自 silu → 加权求和**（≡ 隐层拼接） |

**关键数学**：加权求和 ≡ 隐层拼接，所以拼出来是**一个 k·h_cell 宽的单一专家**，
而不是 k 个小专家各干各的。这才是「拼成专家」。
