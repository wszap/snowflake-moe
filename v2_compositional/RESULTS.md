## ★ 统计修正（Bug9）：CI 与 p 值的正确写法

### 问题

原实现使用：
```python
n_eff = n_perm * n_batch = 20 × 50 = 1000
```
存在**两处统计错误**：

1. **伪重复** —— 同一 batch 内的 20 个 perm 共享同一组 `xb/yb`，非独立样本
2. **非配对** —— permuted 与 learned 在同一 batch 上测得，却按独立样本处理

### 修正

改为 `n_eff = n_batch = 50` 的**配对检验**。

### 修正后结论：H4 依然成立

|---|---|---|---|---|---|

| 0c0cbd | 0.7781 | 0.0035 | 0.0158 | 0.7702 | pass |
| 21fd4f | 0.7712 | 0.0031 | 0.0143 | 0.7640 | pass |
| 9c83b9 | 0.7652 | 0.0028 | 0.0128 | 0.7588 | pass |
| 3e820a | 0.7894 | 0.0029 | 0.0131 | 0.7829 | pass |
| 7f82f8 | 0.7529 | 0.0028 | 0.0128 | 0.7465 | pass |
| 8ded0a | 0.7028 | 0.0029 | 0.0135 | 0.6960 | pass |

```

```

**即使按最保守的 `n_eff=50`（不乘 `n_perm`）重算，10 个 seed 的 CI 下界仍全部 > 0。**

### 论文写法

```
❌ 旧（不要这样写）
core_stat = 0.7663, CI=[±0.0016], p < 1e-300

✅ 新（应这样写）
core_stat = 0.7663 ± 0.0345 (n=10 seeds)
95% CI [0.7416, 0.7910], t(9) = 70.3

并注明：CI 基于 seed 间变异；单次 run 内部采用配对检验
       （permuted 与 learned 在同一 batch 上配对），
       不使用 n_perm × n_batch 作为有效样本数（避免伪重复）。
```

## 🔴 H2「按输入组合」显著 FAIL

```
var_norm = 0.0405 ± 0.0053
95% CI   = [0.03671, 0.04427]
t(9)     = 5.70   （单尾临界 1.833）
→ 显著低于 0.05 阈值，不是边界情况
```

**含义**：wiring 在样本间的变异只有理论上限的约 4%。
模型找到配方后，**对绝大多数输入使用几乎相同的配方** ——
是「组合」（eff≈62，远离 one-hot），但**不是「按输入组合」**。

### 方法论保留意见

`var_norm` 的分母用的是 **one-hot 上限 0.0026**。
但模型实际是约 62 个器官的稀疏混合分布，其理论方差上限**不同于** one-hot。
**归一化基准可能有偏，0.0405 或被低估。**
建议补一个以「eff=62 稀疏分布」为基准的归一化，再下最终结论。

## 一个有价值的副产品：eff 与 var_norm 负相关

```
Pearson r = -0.482
eff 最低(27.37) 的 seed → var_norm 最高(0.0477)
```

**器官用得越集中，样本间变异越大。** 符合直觉，
且提示 eff 与 var_norm 存在内在权衡，值得在论文中讨论。

## 🔴🔴 Dense 对比结果：效率叙事彻底不成立

### 泄漏自检先通过

```
leak_check: 改动位置 16..31 后，位置 0..15 输出最大差异 = 0.00e+00
⇒ ✅ 无泄漏（正确 causal）
```

### 规模扫描（3000 步，各自 seed=0）

| L | d | params | vs Snowflake | loss | Δ vs Snow(1.9160) |
|---|---|---|---|---|---|
| 4 | 192 | 1,799,424 | **0.348x** | 1.23918 | **−0.677** |
| 4 | 256 | 3,185,664 | 0.617x | 1.14157 | −0.774 |
| 4 | 320 | 4,965,120 | 0.962x | 1.03256 | −0.883 |
| **5** | **288** | **5,025,312** | **0.973x** | **1.03461** | **−0.881** |
| 4 | 384 | 7,137,792 | 1.382x | 1.00366 | −0.912 |
| 6 | 320 | 7,431,040 | 1.439x | 0.96557 | −0.950 |

**全部 6 个配置都优于 Snowflake，包括最小的 0.348x。**

### 三个 claim 的命运

| 原文 claim | 判定 |
|---|---|
| `a fraction of the parameters of a dense baseline` | ❌ **彻底不成立** — dense 用 **0.348x** 参数即超越 |
| 同参数下可比 | ❌ Snowflake loss 高 **85.2%**（1.916 vs 1.035） |
| `0.664x FLOPs` 效率优势 | ❌ **同样不成立** — 取胜的 dense 只需 0.348x 量级 FLOPs，Snowflake 反而是它的 **1.91 倍** |

### 根因：不是参数问题，是信息量不对等

`SnowflakeB.forward` 中每个 token 独立变换，
唯一"上下文"是所在 chunk（32 字符）的平均；**无跨 token 注意力、无跨 chunk 信息流、无位置编码**。
dense 修好后有完整因果注意力（可见前 127 token）。

**这是架构层面的不对等，不是调参问题。**

### 论文叙事必须改写

弃用"更高效"，改打**架构发现**：

> 在 TinyStories 字符级建模上，缺少跨 token 注意力的架构
> 即使使用 384 个可组合器官与 0.664x FLOPs，
> 仍显著劣于标准因果 Transformer（loss 1.916 vs 1.035，+85.2%）。
> 说明**跨 token 注意力是该任务上不可替代的归纳偏置**，
> 而"组合式稀疏激活"本身无法补偿其缺失。

这个结论**有发表价值** —— 一个清晰的负结果，且给出了量化边界。

### 可选补救

给 Snowflake 加轻量上下文（chunk 间 GRU / sliding-window attention）后重测，
可分离"记忆点机制"与"缺失注意力"各自的贡献。**需你拍板是否投入。**
